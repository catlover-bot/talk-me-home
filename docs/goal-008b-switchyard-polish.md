## Focused changes selected for verification

Source inspection found that a panel acknowledgement clears current-visit request handles even though the server retains that same visit and inspected equipment. The panel already computes actual public connectivity, but its reached conductors differ only by a subtle color. Its success message names a revision without describing changed terminal power. The fresh compiled baseline confirmed both findings at 1280 x 720 and 1440 x 900. Six local choices disappeared after Apply and one extra Look around restored them. The plate caption had no routing-age label. The manual route comparison began below the initial fold, while exact confirmation and Pause were already visible together when a proposal was pending. [Baseline receipt and review](../artifacts/goal-008b/before-review.json) distinguish these screen observations from human-learning hypotheses.

Each baseline session recorded six selected requests, two approach discussions, two exact confirmations, one manual-tab selection, five piece turns, one Undo, one Reset, one Apply, Start Practice and Pause: 21 recorded control activations. Two turns deliberately exercised draft restoration; these are not minimum-solution counts. One tab selection exposed both manual rows beside the report at 1280 after earlier normal control scrolling, while the same selection at 1440 left the rows below the fold. Confirmation and Pause were visible together in both pending-action images. Switching the discussed approach took one request; restoring the six lost local choices after Apply took one additional Look around. Capture scrolling is recorded separately and is not a measure of human gestures or time.

The implementation keeps the existing mechanics and makes these focused changes:

- A dashed non-color trace follows reciprocal visible contacts from the supply. Terminal prediction and applied power remain separate; the applied miniatures do not move with a draft. Rotation feedback is local, and a terminal-change receipt appears only after the requested layout matches a newer acknowledgement. Pending/rejected Apply does not create a success receipt. The overload text names the three connected public terminals and the two-load rule without choosing an answer.
- The route overview is above the panel, with its installation drawing and operating notes expandable. Both approach tradeoffs remain authored human documents. Private intended-route radios are optional: changing them sends no request, grants no approval, changes no power, and preserves the existing draft and committed work. The exact pending proposal still needs its own decision.
- An exact plate quote sits beside all manual rows, with Pip/source/time and known reported-visit context. Routing and later actions age the report without rewriting it. Dynamic conditions remain explicitly historical; the UI directs the player to the latest report rather than requiring a redundant inspection. Raw provider speech is unchanged and is not assigned fabricated local visit metadata.
- Existing current-visit device/action handles survive panel-only Apply. Round, Pause, resumed-call, different-visit and classified stale-scope guards remain. A delayed pre-Apply result cannot restore current readiness or replace the original attributable plate source. The server's existing validation still invalidates the old physical proposal and requires a new exact confirmation.
- Only confirmed home reveals the actual approach's symbolic departure illustration and a short separately labelled authored reflection. Existing artwork and procedural completion/acknowledgement sounds are reused, with the original gesture, mute/volume and speech-priority behavior. Both OS and application reduced-motion choices retain static cues.

Claims about easier learning or greater enjoyment remain hypotheses for the [optional first-play sheet](goal-008b-playtest.md).
